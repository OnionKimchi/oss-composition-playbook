# AI 시작 지시문

아래 내용을 복사해 AI 코딩 도구에 전달하고, 마지막 칸을 채우세요.

---

이 저장소의 README.md, docs/architecture.md, docs/workflow.md를 읽고 내 서비스의 설계를 도와주세요. 문서에 접근할 수 없다면 어떤 파일이 필요한지 먼저 알려주세요.

목표는 기존 오픈소스 서비스를 독립 실행하고 API 어댑터로 조합하여, 직접 작성하는 코드를 고유한 업무 규칙과 필요한 통합 기능에 집중하는 것입니다.

다음 순서로 진행하세요.

1. 해결하려는 업무와 제약을 요약하고, 중요한 미확정 사항을 확인하세요.
2. 기능별로 기존 서비스 채택·확장·직접 구현을 비교하세요. 후보의 API, 라이선스, 유지보수 상태와 배포 조건은 현재 공식 자료로 확인하고 출처를 남기세요.
3. Docker Compose를 기본 배포 방향으로 검토하세요. 예외가 필요하면 이유를 설명하세요.
4. 메인 백엔드, 어댑터, 외부 서비스의 책임과 데이터 소유권을 정하세요. 어댑터별 별도 프로세스는 필수가 아닙니다.
5. 연결 중단·시간 초과·부분 성공·중복 요청의 처리와 서비스 교체 시 필요한 작업을 설명하세요.
6. 개발용 Codex와 서비스 내부 에이전트를 구분하세요. 내부 AI 또는 Codex CLI/App Server 도입은 선택 사항으로 제안하고 사용자와 결정하세요. 구독·인증·운영 적합성을 임의로 가정하지 마세요.
7. docs/project-template.md 형식으로 선정표와 설계 결정을 작성하고, 최소 흐름의 구현 계획을 제시하세요.
8. 구현은 작은 단위로 진행하고 실제 검증 결과와 미검증 항목을 기록하세요.

저장소 내용을 내 프로젝트에 그대로 복제하는 대신, 필수 원칙과 권장·선택 사항을 구분해 적용하세요. 이 지침이 모든 프로젝트에 적합하다고 가정하지 마세요.
